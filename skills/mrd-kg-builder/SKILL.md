# MRD KG Builder

Use this skill to build the MRD biological QC knowledge graph structure.

This skill is the fourth step in the MRD biological QC pipeline.

## Python Helpers

Prefer bundled Python scripts for graph-ready CSV generation from confidence-scored evidence.

- `scripts/mrdskill_build_mrd_kg_csv.py`: build `nodes.csv`, `relationships.csv`, `review_tasks.csv`, and GraphRAG evidence summaries from `mrd_evidence_scored.csv`. When a full source manifest is available, pass `--sources-csv` so parseable files without extracted evidence still enter the graph as `SourceDocument` nodes.
- `scripts/build_visualization.py`: render a browser-friendly visualization of a generated evidence graph.

Typical use:

```bash
python /path/to/mrd-kg-builder/scripts/mrdskill_build_mrd_kg_csv.py --input-csv data/evidence/mrd_evidence_scored.csv --nodes-csv data/graph/nodes.csv --relationships-csv data/graph/relationships.csv --review-tasks-csv data/graph/review_tasks.csv --evidence-summaries-jsonl data/rag/evidence_summaries.jsonl --sources-csv data/imported/full_corpus_sources.csv
```

Every clinically meaningful relationship generated by the script carries an `evidence_ids` value. Review graph edges with low confidence, candidate-only status, possible CHIP, or weak traceability before using them for automated QC.

It should consume confidence-scored evidence records from `mrd-confidence-rater` and generate:

- ontology
- node schema
- relationship schema
- Neo4j import schema
- graph-ready nodes.csv
- graph-ready relationships.csv
- MRD biological QC rules
- CHIP false-positive rules
- audit workflow recommendations
- GraphRAG-ready graph design

Do not perform broad paper retrieval.
Do not build the paper corpus.
Do not perform raw evidence extraction from papers.
Do not assign final confidence scores from scratch.

Those tasks belong to other skills:

- paper-search: corpus construction
- mrd-evidence-miner: raw evidence extraction
- mrd-confidence-rater: evidence confidence rating

## Primary Goal

Transform confidence-scored evidence into a graph-ready MRD biological QC knowledge base.

The graph should support:

1. MRD biological plausibility checking
2. CHIP false-positive detection
3. cancer-gene consistency checking
4. assay-method interpretation
5. recurrence / relapse risk interpretation
6. longitudinal ctDNA signal interpretation
7. tumor-derived vs non-tumor-derived signal assessment
8. clinical evidence traceability
9. human audit workflow
10. GraphRAG retrieval and reasoning

## Core Design Principle

The knowledge graph must preserve evidence traceability.

Every clinically meaningful edge should link to an Evidence node.

Do not create graph facts without evidence.

Do not collapse evidence from multiple papers into one untraceable edge.

When merging multiple evidence records into one graph relation, preserve:

- evidence_count
- best_confidence_score
- confidence_distribution
- supporting_pmids
- supporting_dois
- contradiction_status
- audit_priority

## Graph Inclusion Rules

Use `graph_inclusion_status` from the scored evidence table.

### auto_include_high_confidence

Create graph relationships directly.

Requirements:

- confidence_score = High
- evidence_strength_score >= 4
- source_traceability_status = fully_traceable or partially_traceable
- graph_inclusion_status = auto_include_high_confidence

### include_as_medium_confidence

Create graph relationships with medium-confidence label.

These may be used for assisted reasoning but not automatic final clinical QC.

### include_as_low_confidence_annotation

Create annotation-only relationships.

These should not drive automated QC decisions.

### candidate_only

Keep in candidate layer.

Do not use for automated QC.

### needs_human_review

Create ReviewTask node and link it to the evidence.

### exclude

Do not include in graph except optionally in rejection log.

## MRD Biological QC Rule Types

Generate rule templates from evidence.

### Cancer-Gene Plausibility Rules

Examples:

- If MRD signal gene is strongly associated with the cancer type, increase biological plausibility.
- If gene is not known for the cancer type and evidence is weak, mark biologically_uncertain.
- If gene-cancer edge is low confidence, require human review.

### CHIP False-Positive Rules

Examples:

- If gene has CHIP risk and no matched WBC filtering, mark possible_CHIP.
- If variant is present in matched WBC, mark likely_CHIP.
- If variant is absent from tumor tissue and present in plasma only, mark possible_false_positive.
- If gene is both tumor driver and CHIP-associated, require context-aware review.

### Tumor-Informed MRD Rules

Examples:

- If variant is tumor-confirmed and tracked longitudinally in plasma, increase MRD plausibility.
- If ctDNA persists post-treatment and evidence supports recurrence association, mark high_MRD_concern.
- If ctDNA clears after treatment, mark treatment_response_support.

### Tumor-Naive MRD Rules

Examples:

- If tumor tissue is unavailable and assay is tumor-naive, require stronger CHIP filtering.
- If CHIP filtering is absent in plasma-only tumor-naive assay, increase false-positive risk.

### Longitudinal Pattern Rules

Examples:

- Rising VAF over serial timepoints supports tumor-derived MRD.
- Persistent postoperative ctDNA supports recurrence risk.
- Reappearance of ctDNA after clearance supports molecular relapse.
- Single low-VAF isolated signal without recurrence evidence requires caution.

### Assay Quality Rules

Examples:

- If assay LOD is higher than observed VAF, mark technical_uncertain.
- If matched WBC filtering is absent, increase false-positive risk.
- If assay has validation cohort and strong specificity, increase reliability.

## Anti-Hallucination Rules

Do not invent:

- evidence records
- PMID
- DOI
- gene-cancer relationships
- confidence scores
- assay metrics
- cohort sizes
- clinical rules

Use only the scored evidence table or user-provided records.

If evidence is missing, mark:

- unavailable
- not_reported
- uncertain
- not_assessable

Do not upgrade evidence during graph construction.

Do not convert Low-confidence annotations into automated QC rules.

Do not merge contradictory evidence without preserving contradiction status.
